# حضانة بدر — ملف تجهيز وتسليم مشروع CCTV

**Project:** حضانة بدر — نظام كاميرات المراقبة  
**Client:** حضانة بدر  
**Stage:** تجهيز ملف أول مشروع للتسليم؛ **ليس محضر استلام نهائي**  
**Project target:** 22 كاميرا IP بالصوت والصورة على الشبكة (العدد المستهدف المبلغ به؛ يتم مطابقته ميدانيًا).

## 1. نقطة انطلاق دقيقة

- سجل الكاميرات: `docs/projects/badr-nursery/camera-inventory.csv`، يتضمن 22 خانة CAM-01 إلى CAM-22، ويُملأ من قراءة الأجهزة الفعلية وليس من التخمين.
- **بيانات كل كاميرا المطلوبة:** Model وSerial No وMAC Address وIP Address وموقع التركيب وSwitch/Port والتحقق من الصورة والصوت وPoE.
- شبكة المشروع بحسب المخطط السابق: SW-01 إلى SW-04 سويتشات مناطق، وSW-05 للتجميع. **هذه تسمية تصميمية تحتاج مطابقة الواقع**.
- حالة المسجل: كان المخطط يتضمن NVR `DS-7732NXI-K4` بعدد 32 قناة، لكن المعلومات الأحدث أفادت بفصله من الشبكة؛ **لا تُدرجه على أنه متصل أو يعمل**.
- توزيع الكاميرات القديم في مسودة BOQ: 9 × `DS-2CD1323G2-LIU` داخلي، 4 × `DS-2CD1021G0-I` خارجي، 5 × `DS-2CD1123G2-LIU` داخلي؛ المجموع **18 وليس 22**. هذه **مسودة تاريخية** لا تصلح لإثبات موديلات الأجهزة الـ22 المركبة أو إصدار الكميات النهائية.
- نوع الكابل المستهدف في المسودة: Cat6 UTP 0.55mm؛ يلزم قياس المسارات وتأكيد مواصفات الكابل المركب فعلًا.

## 2. تجهيز المشروع داخل AZ-CCTV

1. ادخل بحساب المالك إلى `/projects` واضغط **إنشاء / فتح حضانة بدر**. لا تُنشأ نسخة مكررة للمستخدم نفسه عند تكرار الضغط.
2. افتح محرر المشروع، وأضف كل مخطط / دور مع اسمه الفعلي. ارفع مخططات PDF/الصور المتوافقة، ثم عاير المقياس من بعد معروف.
3. ضع الكاميرات من كتالوج المنتجات مع التحقق من أن الموديل يطابق الجهاز الفعلي؛ لا تستبدل معلومة Serial أو MAC بنوع المنتج.
4. وثق SW-01..SW-05 والمنافذ والمسارات ومسافة كل رابط في وحدة CCTV Network، مع تعديل ما لا يطابق التنفيذ.
5. راجع مواضع الكاميرات والتغطية في CCTV System وCCTV Maps، وتحقق من مشاهدة الفيديو وسماع الصوت لكل كاميرا.
6. أنشئ BOQ وحساب الكابلات وPoE من التصميم النهائي، وراجع أسعار/كميات العرض وتوقيع الاعتماد في CCTV Cost.
7. بعد اكتمال المراجعة، جهز حزمة التسليم أدناه وأصدر النسخة النهائية للمراجعة مع العميل.

## 3. حزمة التسليم المطلوبة

| مستند / اختبار | معيار القبول | الحالة |
|---|---|---|
| مخططات As-built | مواقع الكاميرات مرقمة ومتطابقة مع الواقع، وكل طابق/منطقة موثق | قيد الاستكمال |
| سجل 22 كاميرا | Model وSerial No وMAC وIP وموقع كل كاميرا؛ **22/22** بيانات مؤكدة | قيد الاستكمال |
| تقرير فحص الصورة والصوت | اختبار عملي مسجل لكل كاميرا | قيد الاستكمال |
| Network topology | توصيلات SW-01..SW-05 والمنافذ والـuplinks مطابقة للواقع | قيد الاستكمال |
| اختبارات PoE والشبكة | الطاقة والاتصال مستقرة؛ لا يوجد منفذ بلا توثيق | قيد الاستكمال |
| تقرير الكابلات | طول كل مسار، نوع الكابل، نتيجة الفحص والترقيم | قيد الاستكمال |
| تقرير NVR / التسجيل | توثيق الحالة الحقيقية للمسجل ووسيلة حفظ التسجيلات إن وجدت؛ لا ادعاء بوجود تسجيل دون إثبات | قيد الاستكمال |
| جدول كميات نهائي | BOQ محسوب من المنفذ فعلًا، مع فصل التغييرات عن المسودة | قيد الاستكمال |
| تدريب العميل | حسابات المشاهدة والصلاحيات وطريقة الإبلاغ عن الأعطال موثقة | قيد الاستكمال |
| محضر الاستلام | توقيع العميل بعد معالجة الملاحظات | لم يصدر |

## 4. بوابة منع التسليم الخاطئ

**لا تُوسم حزمة التسليم بأنها مكتملة** قبل (1) مطابقة الـ22 كاميرا، (2) تأكيد الصوت والصورة، (3) توثيق الشبكة والمسجل، (4) توقيع واعتماد مستند As-built وBOQ ومحضر التسليم.

لا تُدرج كلمات مرور أو رموز استعادة أو إعدادات وصول سرية في مستندات التسليم العامة.

## 5. مسار الاعتماد داخل التطبيق (Production Candidate)

- من صفحة `/projects` اضغط **إنشاء / فتح حضانة بدر**؛ الملف مملوك للمستخدم المسجل ويتبع سياسات Supabase RLS.
- من محرر المشروع افتح **سجل الفحص والتسليم**. السجل مستقل عن BOQ ولا يسوّي بين شراء معدة وبين تركيبها بالفعل.
- اربط كل `CAM-01..CAM-22` بكاميرا مرسومة واحدة؛ أدخل Model وSerial وMAC وIP والمنطقة والسويتش والمنفذ من قراءة الموقع.
- أدخل اسم الفني وتاريخ الاختبار، وسجّل PASS / FAIL لكل اختبار صورة وصوت وPoE. لا تُدخل PASS دون دليل ميداني.
- حقق ربط الشبكة، واختبارات الكابلات، وتوثيق وضع التسجيل الحقيقي، ومراجعة As-built وتدريب العميل.
- وقّع محضر الاستلام خارج النظام أولًا، ثم دوّن مرجعه وأقر بحالة التوقيع. لا يثبت مجرد تفعيل خيار التوقيع صحة المستند الأصلي.
- استخدم **تقرير فحص للطباعة / PDF** لإصدار تقرير مبدئي. سيظهر بوضوح كمسودة ما دامت الشروط غير مكتملة؛ يجب تدقيق محتواه ومطابقته على الطبيعة قبل تقديمه للعميل.

### قواعد إصدار النسخة المعتمدة

`evaluateHandover` يرفض وصف السجل بأنه جاهز عند نقص أي مما يلي:

1. جميع المخططات مرفوعة ومعايرتها معتمدة.
2. عدد الكاميرات الفعلي على المخطط = 22، وربط كل سجل بجهاز مختلف.
3. تفرد Serial وMAC وIP، وصحة تنسيق العناوين والبيانات الأساسية.
4. نتائج PASS للفيديو والصوت وPoE، مع اسم فاحص وتاريخ صالح.
5. وجود مسار شبكة لكل كاميرا، وإقرار التحقق من الشبكة والكابلات ووضع التسجيل.
6. مراجعة As-built، وتدريب العميل، ومرجع محضر استلام موقع.

**هذا تحقق من سلامة واكتمال البيانات المُدخلة، وليس بديلًا للاختبارات الميدانية أو مراجعة التوقيع.**

### فصل مراحل الإصدار

- **Code readiness:** بناء Node، TypeScript، Vitest، بوابات الجودة، وملف dependencies متزامن.
- **Application readiness:** اختبار إنشاء وحفظ واستعادة مشروع بحساب صحيح، ورفع المخططات، وطباعة التقرير من متصفح حقيقي.
- **Site readiness:** 22 جهازًا مطابقًا، توثيق الشبكة والتسجيل، وتوقيع العميل.
- **Production release:** النشر على `cctv.alazab.com` بعد تحقق نظام الخدمة وNginx والاختبارات الحية. لا يعتبر نجاح GitHub Actions دليلًا على نجاح النشر.

### اعتبارات عدم افتراض المعلومات

لا يُستنتج ارتفاع السقف من قيمة افتراضية في المحرر، ولا يُستنتج طول الكابل من صورة غير معايرة، ولا يُعتبر سويتش SW-01..SW-05 موثقًا ميدانيًا لمجرد وجوده في التصميم. يجب التأكد من بيانات هذه العناصر على الموقع قبل الاعتماد.
